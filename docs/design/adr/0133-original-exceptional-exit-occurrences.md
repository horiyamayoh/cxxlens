# ADR 0133: Original exceptional exit occurrences

Status: accepted

Monet's `control.exit.exceptional_count` requires written throws, unhandled exceptional exits and compiler-selected termination edges. Its noexcept rules additionally require original semantic exception specification independently of lexical and lowering closure. The existing AST CFG and call/action populations do not enumerate implicit escaping call continuations, cleanup resumes and all compiler termination routes.

One original occurrence relation extends the existing physical definition detail and body with an optional atomic count/member/state/profile facet. The population retains a carrier for every actual completed lowering variant, including a genuinely empty one. Written throws, escaping calls, unhandled resumes and termination remain distinct roles; ordinary instructions and actual throw-helper views remain explicit exclusions. A written throw is never counted again solely because its original lowering helper emits a call. Each alternative constructor/destructor lowering variant stays separate; a consumer requires agreement across closed variants rather than adding alternatives.

The compiler analysis schedules already parsed, nondependent written definitions through public `CreateLLVMCodeGen` and `GetAddrOfGlobal`, with their original target, language and code generation options. It neither reparses nor changes parser flags. Admission precedes lowering, covers actual written lambda call operators, and excludes dependent patterns, bodyless declarations and defaulted/deleted definitions from known-zero claims. Actual default/initializer activation gaps remain partial.

Exact LLVM 22.1.0 CodeGen source components observe original function/variant, expression, runtime instruction and EH-emission identities. Original final block/instruction ordinals are independent from AST CFG nodes and elements. Coalescing uses an actual compiler instruction or block identity inside the job; source positions and callee names do not supply semantic joins. The expression FK retains the actual compiler emission source view, which may be an enclosing new/delete or throw expression; it does not establish an implicit cleanup object or AST execution occurrence. The original emitter-method mask independently distinguishes generic selected calls from runtime lowering helpers. Every completed final IR call is checked against those observations. Unsupported target routes and unbound instructions prevent complete membership.

The bounded recorder latches cancellation, quota and callback errors without throwing through compiler cleanup. No compiler pointer leaves the job. Detachment retains original sources, USRs, exact normalized subject associations and unresolved frontiers. The portable SDK validates count/member inventories, worlds, physical definition and variant bindings without lowering again or computing a metric. Missing facets in earlier saved inputs remain unknown; independent semantic noexcept and ordinary CFG facts survive lowering gaps.

The exact static compiler dependency is explicit and uses matching assertion, RTTI and exception ABI settings. The stock provider DSO remains unsupported for this instrumentation. The completion sequence is schema and bounded recorder, detachment and native routing, pure projection, then real original compiler inputs through the independent consumer. There is no general IR graph service or development certification system.
