# ADR 0128: Original compiler template domains

Status: accepted

Monet's template catalog needs actual materialized specialization entities, canonical argument tuples, dependent written occurrences, normalized constraints, lambda capture storage and original instantiation depth. Returned ordinary declaration/call rows do not close those domains. In particular an implicit specialization can be materialized before the written-declaration filter, and a spelling of a constexpr call does not establish that the compiler evaluated it.

The native Clang 22 path admits those subjects in a dedicated bounded original AST pass and emits `cc.template_subject`, `cc.constraint_node`, `cc.lambda_capture`, `cc.template_instantiation_frame` and one original `cc.template_inventory` per exact selected unit/world. Each family has its own atomic original count/ID set/state. Missing scans, omitted members, incompatible profiles, recovery/failure and truncation retain partial populations. Conflicting duplicate payloads do not select a winner. Entity, source, argument, normalization, mapping, layout and stack binding remain independent from finite enumeration. Original optional missing cells are not padded with invented observations.

`clang22-canonical-template-argument-tuple/1` retains original compiler canonical type/declaration/template identities, exact integral widths/sign/value, typed structural values, original member/base/array paths and ordered packs. Unsupported or dependent values remain unavailable independently from specialization admission. Pretty types, addresses and an expression hash do not replace an original tuple. Distinct physical argument-use subjects remain available for per-primary distinct tuple consumers.

Written dependent type occurrences include every actual dependent TypeLoc construction, including compound pointer, reference, array and function types. Exact compiler TypeLoc classes distinguish distinct constructions that share a source range. Concept specialization expressions retain their compiler-bound concept and canonical argument tuple as actual argument-use subjects.

The corrected subject and inventory admission profile is `clang22-original-template-domains/2`. The earlier `/1` admitted a subset of dependent type constructions and omitted concept specialization argument uses. Saved `/1` rows remain readable, with their exact evidence and independent constraint, capture and frame populations retained, but they cannot close the full subject population. An inventory cannot promote subject rows from a different admission profile. Each dependent TypeLoc row also exposes its exact `type-loc:<TypeLocClass>` occurrence discriminator as an opaque compiler value; a global ordinal or a shared source range is insufficient for cross-unit occurrence identity.

`clang22-sema-associated-constraint-normalization/1` uses the compiler's normalized associated constraints. An original root is depth 1; original ordered child edges add one level, including concept and fold wrappers. Each path retains its parameter mapping. A failed normalization retains its admitted root and incomplete tree. Source conjunctions or concept names do not substitute for normalized nodes.

`clang22-original-template-instantiation-stack/1` installs the observer in the source-private `SemaConsumer::InitializeSema` callback before the first parsed source declaration. Stock `ParseAST` initializes its existing callback chain before that hook, so the newly installed observer initializes itself there. Begin/end events retain the original compiler kind, source, parent and `isInstantiationRecord` depth. The original parse trace freezes at the AST-ready boundary before extraction or requested constraint normalization can add analysis events. Recovery, unbalanced events and resource/cancellation failures retain the frontier. Memoization and other compiler noninstantiation records remain observable but do not add instantiation depth.

`clang22-lambda-capture-storage/1` joins each capture to the compiler's actual closure field and layout. Reference captures use the actual field storage. Unknown fields are retained separately from known offsets/sizes and from the complete capture population. No host ABI assumptions replace layout.

The public SDK's `project_template_domains` owns original annotated evidence, validates actual unit/world/member/source FKs and preserves all original query plans, results and side channels. Raw compiler USRs join the existing normalized entity key through its exact `clang-usr:` framing; missing keys stay unknown and contradictory keys stay conflicting. Subject identity, enclosing owner identity and captured object identity remain separate from argument, storage layout and population completeness. It does not calculate Monet metrics or reconstruct a second name/type resolver. Both entry paths validate all original input rows and retain only the source rows referenced by actual template observations. Bounds cover rows, condition expansion, members, retained bytes, evidence references, nested work and cancellation before allocation.

The AST/stack profile does not claim original final SFINAE candidate exclusions or reached constant-interpreter calls. Those require explicit exact compiler event instrumentation; an ordinary substitution frame, trapped diagnostic or AST call proxy does not close either catalog domain. The static native worker can link instrumented exact upstream compiler translation units without changing installed public SDK ABI. Until those event domains are implemented and bounded, the corresponding full catalog results remain unavailable.

This is ordinary analysis data and input consistency. It introduces no provider certificates, test-SHA ledger or formula/model/rule replay.
