# Original lowering routes and resource bindings

The independent consumers are Monet's exceptional-route, concurrency,
portability and resource analyses. This wave retains original compiler facts;
consumer rules and numeric policies remain outside the native producer.

## Original exceptional routes

Each admitted physical definition retains its original ABI lowering alternatives.
For each alternative, the final original LLVM function supplies its entry block,
all blocks, instruction counts and all terminator successor occurrences. An
Invoke instruction names its distinct normal and unwind successor occurrences.
These identities are scoped to that original lowering alternative. They never
identify an AST CFG block, AST statement or runtime object version.

Topology membership, original call binding, exception boundary classification,
catch interception and propagation disposition are separate axes. A reachable
termination block alone does not prove a noexcept escape: an earlier exception
may have been caught before unrelated explicit termination. Qualification needs
the original compiler boundary and propagation correspondences. Unsupported
personalities and missing correspondences retain an explicit frontier.

Original cleanup emissions retain their LLVM instruction placement separately
from registration and emission callback ordinals. The existing stored function
exception specification remains independent of LLVM call attributes. Cleanup
object identity, runtime version, alias closure and acquire/release correspondence
are not established by a lowering graph or destructor target.

The standalone `project_exceptional_routes` SDK projection preserves carrier,
topology, placement, successor, boundary declaration and stored specification
states separately. It validates every original input row, retains orphan records,
and reports measured successful work and conservative storage usage. It performs
no path search or exceptional-escape qualification. A supported partial physical
definition inventory can prove an observed member's unit binding without proving
the whole definition census complete.

## Atomic and type-trait expressions

Only actual `AtomicExpr` nodes receive the atomic facet. The compiler enum and
registered enum spelling are preserved under
`clang22-original-atomic-expression/1`. Pointer, success-order and failure-order
operands use exact original syntax bindings. C11 and OpenCL atomic initialization
have an initialization value rather than a memory-order operand; failure order
is applicable only to the actual compare-exchange operations. Compiler-evaluated
order values remain separate from operand bindings, and missing or dependent
values remain unknown. Non-atomic builtin calls do not acquire this facet.

Only actual `UnaryExprOrTypeTraitExpr` nodes receive
`clang22-original-type-trait-expression/1`. The original trait kind, argument
form and canonical argument type remain separate from the expression result
type. Expression-form arguments have an exact original expression binding.
The result is retained only after successful compiler integer evaluation;
dependent, variably modified and unsupported results preserve their state.
Future compiler symbols are retained without becoming recognized consumer kinds.

Source include populations use original inventory, processed include source and
compile-unit main-source associations. A global same-world file list does not
establish that every translation unit entered every file. A missing inventory
for an independently associated source remains unknown, and a unit without any
original source association retains an explicit unit frontier.

## Physical definitions and AST CFG

A coroutine body binds the actual original definition declaration and the actual
`CoroutineBodyStmt`. This does not close its lowering or activation population.
The existing single Clang CFG already enables lifetime ends, implicit and
temporary destructors, scopes and EH edges. Original CFG elements retain their
block, element index, compiler kind and exact statement/declaration bindings.
Missing optional bindings do not erase structural element membership.

Resource lifetime ends reuse actual `CFGLifetimeEnds` and their declaration
bindings. Move effects require the compiler's selected move constructor or move
assignment and original source/destination operands. Ownership attributes retain
their structured compiler payload and bound formal slots. Address origins and
escape destinations require actual compiler operands and storage bindings.
Neither xvalue syntax, attribute spelling nor source containment substitutes.

The special-member and address-transfer census profiles cover the admitted written
AST only. Implicit/default activation endpoints retain an explicit frontier. An
original direct address fact describes storage and destination operands; it does
not establish pointee alias closure, current object version or lifetime validity.

## Bounds and completion

Every original input is validated and charged before retained allocation. Work,
storage, cancellation and partial compiler streams remain independent. Known
empty populations require their own complete original count and ID census;
missing populations remain unknown. Existing claim conditions, worlds,
contributors, coverage and guarantees are retained by every projection.

The source scope is the private compiler adapter, relation registry, public SDK
facades and ordinary schema/header/native/package tests. The released SDK123
prefix remains immutable. Static instrumented compiler linkage is supported only
where the matching exact source objects are actually linked; the stock shared
compiler and uninstrumented execution paths retain unsupported or unknown axes.
